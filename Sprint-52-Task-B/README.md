# Task B:  Categorize The Mandarin Candidate's Actual Failure Cases And Identify What Would Push It Further

(Continuing on work from from Sprint 51 Task B)

User story: As a team about to revise the Mandarin candidate, we want the specific failure cases from its actual evaluation run categorized by type, so the revision targets real, identified patterns instead of a general sense that it needs to be "better."

Acceptance criteria:

Go through the actual wrong language outputs from the evaluation run, roughly five cases, and categorize each one by what specifically went wrong, wrong script, English leakage, a different Chinese variety, or something else.

Go through the below threshold quality cases and categorize each by root cause, meaning error, unnatural phrasing, or something else specific, not just "low score."

From these categorized patterns, identify two or three concrete, testable hypotheses for what would close the quality gap, for example a specific data pattern to add, or a specific type of example currently underrepresented.

Deliver a short table, failure type, count, and one representative example each, plus the two or three hypotheses, not a general narrative summary.
